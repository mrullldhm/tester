# Audit-motivated exclusions, before first mining run

In addition to hypotheses.md, exclude confirmation close outside the original [L,H] interval (fair clipping would otherwise conceal an already breached barrier), levels whose origin-to-confirmation interval crosses a roll, and backward/restored state events. Preserve the source event table. Test original fair and strict one-tick barrier fair as separate models, both in combined BH. Only sequence-family cells receive the quarter-leg limit variant. No limit-entry timing threshold or cell categories will be optimized. Limit uses fixed touch price even on favorable gaps because open is prohibited as a feature; results are geometric diagnostics, not an engine P&L simulation. Expiry is original first barrier passage, no session flatten, so overnight results are explicitly not deployable intraday.

Before first scan: replacement feature is missing on dual-point updates; only single-point updates provide unambiguous replacement=0/1. Entry-bar stop touches are included as losses, including a stop on the entry bar; a target on the entry bar is excluded as unknown entry/target order. This resolves the entry-bar ambiguity wording in hypotheses.md without consulting results. `supplement.py` overwrites the initial limit eligibility in prepare.py before mining.

After the first complete scan, an implementation audit of the limit experiment showed that its asymmetric ambiguity treatment (including entry-bar stop losses, excluding entry-bar target cases) makes its negative edge a lower-bound diagnostic, not a calibrated binomial test. Those 2,850 tested cells remain in the total 15,608-cell budget. `qualify.py` assigns their p-values 1 for the final BH calculation, preventing these invalid null tests from increasing the acceptance threshold for original/tick cells. The original p/BH columns remain for transparency; final decisions use `valid_p`, `bh_valid`, `q_valid`, `qualified`. No thresholds were tuned. No limit profitability discovery is claimed. Additional raw-touch entry/target ambiguity bounds are descriptive arithmetic, not a search or hypothesis test.

One follow-up stress round, declared after selection and before executing stress.py: take every one of the eight valid tick-model survivors from qualify.py, restrict independently to leg>=11 ticks, non-15:59-CT confirmations, single-point updates, low events only, high events only. Test every restriction cell with n>=300, retain failures, and jointly redo BH with the entire original 15,608-test budget. No further mining round is planned. These are exploratory robustness tests, not independent replication.
